How the pieces fit

The browser sends your text to a small Python server. The server hands it to Laya, the model that does the actual judging. The answers come back as three numbers and a label, and the page turns them into gauges. The dashed area is the classification layer.

The important part

The classification layer: Laya

Every judgment on screen comes from one function call: router.predict(state, questions). This section explains what that call actually is.

It classifies. It doesn't write.

Most people would reach for a chat model here: send the message, ask “what's the tone?”, read the reply. Laya works differently. It is a non-autoregressive decision engine: an encoder model (ModernBERT-large, 421M parameters, for English) that reads the whole message and your questions together, then answers all of them in a single forward pass. It never generates a sentence.

We ask it three questions

Laya's vocabulary is three kinds of question, called primitives. Each one maps to one control on the page. This is the real definition from backend/laya_engine.py, shortened:

"tone": {
  "type": "choice",
  "instructions": "Classify the emotional tone of this message.",
  "criteria": {
    "friendly": "warm, kind, positive",
    "passive-aggressive": "indirectly hostile, sarcastic or icy politeness",
    ... neutral, angry, anxious
  }
},
"formality": { "type": "score", "criteria": ["very informal slang", ..., "very formal"] },
"fight_risk": { "type": "noul",  "instructions": "Is this message likely to start a fight?" }
QuestionPrimitiveWhat Laya returnsWhat you see
TonechoiceTop label plus a probability for each of the 5 optionsColored pill and 5 bars
FormalityscoreA position on an ordinal scale (0 to 4)Slider, shown as 1 to 5
Fight risknoulOne calibrated probability, 0 to 1Thermometer, and the “sleep on it” banner above 60%

Laya picked neutral, which is wrong for this message. But the right answer sits in second place, with double the probability of angry. That is useful to know, and it's why we pass all five probabilities to the page instead of only the winner.

The router picks the model for you

Laya ships as three checkpoints. The Router looks at the script and language of each message (under a millisecond, per the README) and sends it to the right one. English goes to the 421M-parameter English model. Hebrew, Arabic, Hindi and 100+ other languages go to a smaller multilingual model, which is faster. In the app you get this for free: the Hebrew test below took 42 ms.

The small translation step in between

Laya's raw numbers aren't quite what the page needs, so our wrapper does three small conversions. This is the only logic we wrote around the model:

Laya saysWrapper doesPage gets
probabilities for 5 tonesNormalizes them to sum to 1, takes the largest as the labelLabel, confidence, 5 bars
score on a 0 to 4 scaleAdds 1 and clamps to 1 to 5Formality slider
noul probabilityClamps to 0 to 1Fight-risk thermometer

A first version of the wrapper ignored the real tone probabilities and made up a spread from the confidence value. Testing against real output caught it, and it's fixed.

How it got built

One orchestrator agent wrote the API contract first, then launched three workers in parallel, each owning separate files so they couldn't collide.

Backend agent

FastAPI server, the Laya wrapper, a rule-based mock fallback so the app runs even without the model, and 16 tests.

Frontend agent

The page itself: textarea, animated tone pill, formality slider, risk thermometer, language badge, light and dark themes.

Docs and QA agent

README, a one-command launcher, and a smoke test that sends sample messages, including Hebrew.

After that we installed the real Laya, compared its output with the wrapper's assumptions, and fixed what didn't match.

What's been checked, and what hasn't

  • VerifiedAll 16 backend tests pass. The smoke test passes in mock mode. Real Laya loads and answers through the running server, including three requests at once.
  • FixedTwo real bugs found while testing: the model loaded on the first keystroke and every keystroke raced to load it, and concurrent requests crashed the server with a Mac GPU (Metal) error. It now loads once at startup and runs one request at a time.
  • WeakLaya's base model misses subtle passive-aggression (see the worked example). Formality barely moves: all five messages landed between 1.9 and 2.4. The README warns that the base models are near chance on custom labels until fine-tuned.
  • SlowerAbout 40 to 110 ms per message on this Mac, not the roughly 33 ms the README benchmarks. Still fast enough for live typing. Startup takes 30 to 60 seconds while the model loads.
  • Seen workingIn a browser, against real Laya: a polite 1,233-character career question came back neutral 53%, fight risk 6%, formality 2.8, with Copy & Send turned green. An angry message filled the thermometer to 71% and showed the “sleep on it” banner.
  • Flaw foundIf a request fails (for example the server restarts mid-typing), the page shows the error but leaves the old gauges on screen, so they look current when they are not. The page should grey them out or clear them.
